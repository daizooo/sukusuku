# すくすく（Androidネイティブ版）

[docs/native-app-rewrite.md](../docs/native-app-rewrite.md) の案Dにもとづく、Expo(React Native)の
プロジェクト。ルートのNext.js（PWA）とは**独立したプロジェクト**で、依存もここで
完結している（npm workspacesにはしていない）。バックエンドは `supabase/` を両方から共有する。

**フェーズ3（通知）まで終わった。** タブバーはPWA版と同じ6つ
（ホーム / 予定 / リスト / 記録 / 保活 / 設定）で、**6つとも中身が入っている**。
記録も授乳・搾乳・おむつ・体温・成長曲線がそろい、**予定・次の授乳の目安・検温の
お知らせもこのアプリに届く**（FCM）。**PWA版を開いておく必要はもう無い。**

> **2026-08-27〜09-17は止めていた（凍結）。** その間にPWA側の授乳が**セット制**へ
> 作り直されたので、再始動にあたって数え方をそちらへ揃えた。いまはPWA版と同じ
> 「左5分 → 右5分 → ゲップ5分で1セット、区切りごとにお知らせ1回、ゲップまで
> 終われば計測も止まる」で動く（docs/native-app-rewrite.md の【現況】）。

## いま入っているもの

| | 中身 |
| --- | --- |
| `app/` | 画面（Expo Router）。`login.tsx`（ログイン）と `(tabs)/`（下のタブバーと各タブ） |
| `src/components/` | 画面の部品。`log/`（記録タブ）と `ui/`（入力欄・選択肢などの共通部品） |
| `src/lib/` | Web版から**そのまま持ってきた**計算・API層。`@/` はこのフォルダを指す |
| `src/lib/offline/` | 端末内に控える仕組み（SQLite）。読みは控え先出し、書きはoutboxで後送り |
| `src/lib/nursingTimer.ts` | 授乳1セット（左・右・ゲップ）のタイマー。計測中の値は端末に控える |
| `src/lib/nursingAlarm.ts` | お知らせを前面サービスへ預ける層。無い環境では振動だけに落とす |
| `src/lib/push.ts` | 予定などのお知らせを受け取るための許可・登録トークン・通知チャンネル |
| `src/lib/nursingState.ts` | 「いま授乳中」をサーバーへ預ける（「そろそろ次の授乳」を止めるため） |
| `src/lib/appLinks.ts` | お知らせをタップしたときの飛び先。PWA版のURLの決まりと同じ対応 |
| `src/components/log/` | 記録の入力画面。授乳・ミルク / おむつ / 体温 |
| `src/types/` | ドメイン型とSupabaseの生成型。Web版と同じもの |
| `modules/nursing-alarm/` | 前面サービス（Kotlin）。授乳中だけ動き、区切りが5分に達したら1回鳴らす |

`src/lib/api/` と `src/lib/dateUtils.ts` などはWeb版(`../src/lib/`)からのコピー。凍結側は動かさない
前提なので分岐していく心配は小さい（docs/native-app-rewrite.md §1）。作り直したもの・
持ってこなかったものは次の3つ。

- `pushSubscriptions.ts` / `nursingAlarms.ts` / `push.ts` — 受け取り方がWeb PushからFCMへ
  変わるので作り直した。宛先の表は同じで `kind` だけが違う（docs/notifications.md §11）
- `alarm.ts` — 鳴らし方は前面サービスへ。長短の規則だけ `src/lib/alarmPattern.ts` と
  `modules/nursing-alarm/.../AlarmPattern.kt` に持ってきた
- `notificationCleanup.ts` — 用が済んだ通知を閉じるもの。判断に記録・体温・予定・計測中の
  授乳がまとめて要るが、こちらはそれぞれ別のタブが持っているのでまだ入れていない
  （docs/notifications.md §10）

## 授乳はどう数えて、どう鳴るか

**左5分 → 右5分 → ゲップ5分で1セット。** 区切りが5分に達すると**1回だけ**鳴る。
鳴らし続けないのは、ほしいのが「次へ移る合図」だけで、鳴り続けると赤ちゃんも親も
休めないため。ゲップの5分まで終わればそのセットは完了で、計測も止まる。
数え方はPWA版（`src/lib/nursingTimer.ts`）と同じで、鳴らす場所だけが違う。

```
[画面] 左/右/ゲップをタップ
  └ src/lib/nursingTimer.ts が「いまどの区切りを何時から測っているか」を前面サービスへ預ける
       └ 常駐通知「授乳 0分 左」を出し、自分で経過時間を数える
            └ 5分に達したところで 音（USAGE_ALARM）+ 振動 を1回
[画面] 区切りの切り替え → 新しい baselineAt で預け直す
[画面] 停止・記録の保存・リセット → サービス終了・常駐通知も消える
[サービス] ゲップが5分 → 鳴らして数えるのをやめ、通知を「タップして記録してください」に変える
```

- 画面が消えていても、アプリを閉じていても、圏外でも鳴る。マナーモードでも鳴る
- 音量は端末の**アラーム音量**に乗る（夜中に鳴らすものなので着信音量とは分ける）
- 聞き逃しても、通知バーに「授乳 3分 左」と出ているので分かる
- アプリを閉じたまま授乳を終えた場合は、通知が「授乳が終わりました／タップして記録して
  ください」に変わって残る。アプリを開くと同じ締めが行われ、通知も消える
- 記録に入るのは**左右の分数だけ**。ゲップは飲ませた時間ではないので残さない
- 表示している時間はいまのセットのぶんで、記録に入るのは全セットの合計。急いで飲ませ
  始めて途中から記録したときのために、測れなかったセットを数で足せるようにしてある
- **端末のバッテリー最適化から除外する設定を1回入れておく**（設定 > アプリ > 電池 > 制限しない）。
  前面サービスは強い部類だが、機種によっては切られることがある

前面サービスは開発ビルドにしか入らないため、**Expo Goで開いた場合はアプリを開いている間の
振動だけ**になる（記録タブの下にその旨が出る）。

## 圏外でも記録できる

授乳中に電波が悪くて記録できないのがいちばん困る形の失敗なので、記録は端末内(SQLite)に
先に入れてから送る（docs/native-app-rewrite.md §6）。

- 起動直後は端末の控えが出る。サーバーの返事は待たない
- 圏外で付けた記録は「未送信」と出て、電波が戻ったときにまとめて送られる
- 送る順番は付けた順のまま。1つでも送れなければそこで止めて、次の機会に続きから送る

## お知らせはどう届くか

**2種類あり、経路が別。** 混ざりやすいので分けて書く。

| | 誰が鳴らすか | サーバーを通るか |
| --- | --- | --- |
| 授乳の計測中のお知らせ（区切りが5分） | 前面サービス（この端末） | 通らない |
| 予定 / 次の授乳の目安 / 検温 | Edge Function → FCM → OS | 通る |

下の3つは設定タブの「通知」をオンにすると届く。**文面はEdge Functionが作るので、
PWA版で見ていたものと同じ**（docs/notifications.md §11）。タップするとその用件の画面が開く
（検温なら体温の入力画面）。

- 宛先は `push_subscriptions` に `kind = 'fcm'` の行として入る。PWA版の端末と同じ表なので、
  **家族のうち片方がPWA版のままでも両方に届く**
- 授乳中は「そろそろ次の授乳」を止める。飲ませ終えて記録するまでの間も止める
  （`src/lib/nursingState.ts`。これが無いと飲ませ終えた直後に飛ぶ）
- Expo Goでは受け取れない（FCMの設定が入らないため）。設定タブにその旨が出る

## 動かす

```bash
cd mobile
npm install
cp .env.local.example .env.local
# .env.local に Supabase の値を入れる（ルートの .env.local と同じプロジェクト）
npm start
```

通知を使うビルドを作るときは、Firebaseコンソールから落とした `google-services.json` を
`mobile/` に置く（コミットしない。取り方は docs/notifications.md §11）。
`npm start`（Expo Go）で画面を見るだけなら無くてよい。

Web版と同じメールアドレス・パスワードでログインできる（`signInWithPassword`）。
一度ログインすればセッションは端末(AsyncStorage)に残るので、2回目からはログイン画面を通らない。

### `.apk` を作る

前面サービス（Kotlin）とFCMの設定はExpo Goに入っていないので、**アラームと通知を
実機で試すには `.apk` を作って入れる必要がある**。

**いつもはCIが作る。** `mobile/` を触ったPRでGitHub Actionsが走り
（`.github/workflows/mobile-apk.yml`）、実行ページの Artifacts から `.apk` を落として
端末に入れられる。`src/` をVercelのプレビューで確かめるのと同じ形。

リポジトリの Settings > Secrets and variables > Actions に次が登録されている前提で動く。
未登録だとビルドは通しつつ配る手前で止まる。

| Secret | 中身 |
| --- | --- |
| `EXPO_PUBLIC_SUPABASE_URL` / `EXPO_PUBLIC_SUPABASE_ANON_KEY` | Web版の `.env.local` と同じ値 |
| `GOOGLE_SERVICES_JSON` | `google-services.json` の中身そのまま（通知の宛先。docs/notifications.md §11） |

#### 端末に入れる

PRの `build` が緑になったら、実行ページの **Artifacts** にある `sukusuku-apk-<PR番号>` を
落とす（zip。解凍すると `app-release.apk`）。

- **PCから**: 落として解凍し、Googleドライブ経由かUSB接続で端末へ送って開く
- **端末だけで**: ChromeでGitHubに**ログインした状態で**同じページを開いて落とし、
  「ファイル」アプリで解凍して開く（未ログインだとArtifactsは落とせない）

入れたあと、**最初の1回だけ**次を済ませる。

| | |
| --- | --- |
| 提供元不明のアプリ | インストール時に聞かれるので、Chrome（またはFiles）に対して許可する |
| 通知 | 設定タブで「通知」をオンにすると聞かれるので許可する。無いと常駐通知が出ず、お知らせも鳴らない |
| 設定タブの「通知」 | オンにする（端末ごと）。予定・次の授乳の目安・検温のお知らせがこの端末へ届くようになる |
| バッテリー最適化 | 設定 > アプリ > すくすく > 電池 > **制限しない**。ここを外さないと機種によっては前面サービスが切られる |

PWA版とは別アプリとして入るので、ホーム画面に「すくすく」が2つ並ぶ。
更新は同じ `.apk` を上書きインストールすればよく、消す必要はない。

手元のPCで作ることもできる。**Android SDKが要る**（Claude Code側の環境では通せない）。

```bash
npm run prebuild   # android/ を生成する（modules/nursing-alarm も自動で組み込まれる）
npm run android    # USB接続した端末へインストールする
```

ストアには出さず `.apk` を自分たちの端末に直接入れる方針（docs/native-app-rewrite.md §8）。
署名鍵(keystore)はリポジトリにコミットしない。

### 実機で確かめること

1. 左を始めて画面を消し、5分で1回鳴るか（そのあと鳴り続けないか）
2. 鳴ったあと右へ切り替え、また5分で鳴るか
3. ゲップまで進めて、5分で鳴ったあと計測が止まるか。通知が「記録してください」に変わるか
4. アプリを閉じたままゲップの5分を過ぎ、開き直したときに止まった状態になっているか
5. マナーモードでも鳴るか。音量がアラーム音量に乗るか
6. 常駐通知の分数が進むか。タップでアプリが開くか
7. 機内モードで記録を付け、戻したときに送られるか（「未送信」が消えるか）
8. おむつを記録して、ボタンの「おしっこ◯回・うんち◯回」が増えるか
   （「両方」はどちらにも1回ずつ数える）
9. 設定タブで通知をオンにし、数分後の予定にリマインダーを付けて届くか
   （アプリを閉じていても届くか。タップでアプリが開くか）
10. 検温のお知らせをタップして、体温の入力画面が開くか
11. 授乳を記録したあと、設定した間隔で「そろそろ次の授乳」が届くか。
    授乳中（計測中・記録待ち）の間は届かないか
12. 通知をオフにすると届かなくなるか（オフ→オンで戻るか）
