# ホーム画面のウィジェット（2026-10-14）

最初のタブに選べる4つ（予定・リスト・育児・家計）を、ホーム画面からワンタップで開けるようにする。
よく使い、記録も多い育児・家計は、タブを開くだけでなく**入力画面まで直接開く**。

## 1. 範囲

- **ネイティブ版（Androidの `.apk`）だけ。** Expo Go・iOS・PWA版（`src/`）には無い
  （ルートの `CLAUDE.md`「ネイティブでしかできないもの」）。Expo Go には部品が入っておらず、
  読み込むだけで落ちるので、`mobile/src/widgets/availability.ts` で確かめてから読み込む
- 部品は `react-native-android-widget`。ウィジェットの見た目は JSX で書き、裏（ヘッドレスJS）で描く
- 置き方: ホーム画面を長押し →「ウィジェット」→「かぞく手帳」

## 2. 種類

**1段は4×1**（見出しは出さない。ホーム画面の場所を取らないため）。単体の3つと、タブに段を重ねた3つがある（§2.4）。

| 名前（`widgetNames.ts`） | 追加画面の名前 | 中身 | 押すと |
|---|---|---|---|
| A. `TabLauncher` | タブ | 予定・リスト・育児・家計のボタン | そのタブを開く |
| B. `CareQuick` | 育児 | 次の授乳の目安・授乳・おむつ・体温 | 目安は育児タブ（読めないときは押すと更新）、ボタンは各入力画面 |
| C. `MoneyQuick` | 家計 | 支出・収入・振替・レシート | 各入力画面、レシートは撮影 |
| `TabsCareMoney` | タブ＋育児＋家計 | A・B・C の3段（4×3） | 各段と同じ |
| `TabsCare` | タブ＋育児 | A・B の2段（4×2） | 各段と同じ |
| `TabsMoney` | タブ＋家計 | A・C の2段（4×2） | 各段と同じ |
| `TabsCareMoneyTight` | タブ＋育児＋家計（縦詰め） | A・B・C の3段を4×2に収めたもの | 各段と同じ |
| `TabsCareMoneyInline` | タブ＋育児＋家計（横並び） | 同上。アイコンと名前を横に並べる | 各段と同じ |

**配色はアプリと同じ（ライトだけ）。** アプリは `userInterfaceStyle: 'light'` で、端末がダークモードでも
ライトのまま出す。ウィジェットも同じで、ダーク用の絵は作らない（ルートの `CLAUDE.md`「配色」）。
色は `mobile/src/lib/theme.ts` をそのまま使う。

**まとまりごとに地の色を1つ割り当てる**（2026-10-14。最初の版は全部が淡い色の四角で、おむつ・家計・タブの青が重なり、
どのボタンがどのまとまりか分からなかった）。単体でも重ねても同じ見分け方になる（`mobile/src/widgets/parts.tsx` の `TONES`）。

| まとまり | 地 | ボタン |
|---|---|---|
| タブ | 白 | 四角を持たない灰色のアイコン（下のタブバーと同じ「画面を移る」見た目） |
| 育児 | 琥珀（amber-100。授乳の色） | 白い四角。アイコンは記録の種類の色、名前は灰色 |
| 家計 | 青（blue-100。家計タブの差し色） | 白い四角。アイコン・名前とも青 |

- 単体は外枠をそのまとまりの地で塗る。重ねたものは外枠を白にし、育児・家計の段がそれぞれ自分の地（`GroupBox`）を持つ

**追加画面の見本（`previewImage`）**: `mobile/assets/widget-preview/*.png`。無いと追加画面で全部アプリのアイコンになり、
見分けがつかない（2026-10-14、最初の版で起きた）。見た目を変えたら見本も作り直す。見本はウィジェットのJSX（`renderWidget`）をそのままHTMLに描き直して撮ったもので、手で描いた絵ではない（コードと見本がずれないように）。

### 2.1 A. タブ

- 押したタブでアプリを開く。最初のタブの設定（`users.start_tab`）に関係なく、押したタブが開く
- データは読まない。ログインしていなくても、圏外でも同じように出る
- 横長なら横一列、正方形に近い大きさへ変えたら2段に並べる

### 2.2 B. 育児

- 左に**次の授乳の目安**の時刻だけを出す（前回の授乳は出さない）。決め方は育児タブの見出しの「次の授乳」と同じ
  （`feedingSchedule.ts` の `resolveLastFeeding`・`nextFeedingSchedule`。家族の端末の計測中・記録待ちも前回の授乳に数える）
  - 家族のだれかが測っている間は「授乳中」。記録が無ければ「—」。読めなければ「要ログイン」などの一言
  - **「あと◯分」は出さない。** ウィジェットは30分ごとにしか描き直されないので、時間とともに変わる値はすぐ古くなる。時刻なら古くならない
  - 目安の欄を押すと育児タブを開く。**読めなかったときだけ、押すとその場で読み直す（更新）。**
    見出しに「読めません（理由）」、値に「押して更新 ↻」を出し、押したら読み終えるまで「更新中…」にする
    （2026-10-17、「読めません」のまま戻らなかった。いつも押すと更新にしたところ、押しても変わって見えず、
    育児タブも開けなくなったので2026-10-18に直した）
  - 理由は、時間切れ（8秒）・通信できません・エラーの文言（40字まで）。原因を実機の画面で見分けるために出す
- ボタンは授乳・おむつ・体温。**搾乳は置かない**（授乳の入力画面にまとめてあり、頻度も少ない）。
  飛び先はお知らせのタップと同じ（`/care?open=milk` など。`mobile/src/lib/appLinks.ts`）
- **ウィジェットから直接は保存しない。** 押し間違いで記録が増えないよう、必ずアプリの入力画面を通す

### 2.3 C. 家計

- ボタンだけ（今月・今日の支出は出さない）。データを読まないので、ログインしていなくても同じように出る
- 支出・収入・振替は記録の入力画面をその種類で開く（`/money?open=income` など）。レシートは撮影から始める（家計タブの「レシートを読む」と同じ）

### 2.4 タブに段を重ねたもの（2026-10-14に追加）

- タブ（A）の下に、育児（B）・家計（C）の段を重ねて1つのウィジェットにしたもの。3通り（タブ＋育児＋家計・タブ＋育児・タブ＋家計）
- 段の中身は単体と同じ部品（`TabsRow`・`CareRow`・`MoneyRow`）を積むだけ（`mobile/src/widgets/CombinedWidgets.tsx`）。単体を直せば重ねたものも同じに変わる
- 育児の段を含むものは、単体の育児と同じく30分ごと・アプリを閉じたときに描き直す

### 2.4.1 3段を4×2に収めたもの（2026-10-14に追加）

4×3（高さ180dp）は3段だと場所を取るため、同じ3段を4×2（最小高さ110dp）に収める2つを**4×3のものとは別に**足した。
どちらも段の中身（ボタンと飛び先）は4×3と同じで、寸法だけを `mobile/src/widgets/parts.tsx` の `DENSITY` で変える。

| | 4×3（`normal`） | 縦詰め（`tight`） | 横並び（`inline`） |
|---|---|---|---|
| ボタンの並び | アイコンの下に名前 | アイコンの下に名前 | アイコンの横に名前 |
| アイコン／名前 | 22dp／11sp | 14dp／10sp | 16dp／11sp |
| ボタンの高さ（幅340dpのとき） | 約45dp | 約27dp | 約27dp |
| 育児の「目安」 | 見出し＋値（19sp） | 見出し＋値（13sp） | 「目安 12:30」の1行（値15sp） |

- 3段を110dpに入れるため、ボタンはAndroidの目安（48dp）より低くなる。押しやすさは実機で見る
- 横並びの「目安」は、時刻のとき以外（要ログイン・授乳中など）は見出しを省いて小さめに出す（長くて入らないため）
- 幅が狭い（250dp前後）と、横並びの「レシート」は欠ける

### 2.5 やめたもの

- **ToDo・買い物（リストの項目を出すもの）は2026-10-14にやめた。** ウィジェットの上で項目を追加・削除できないなら要らない、という判断。
  Androidのウィジェットは文字の入力欄を持てない（追加はできない）ため
- 家計の金額の表示と「金額を隠す」設定も、金額を出さなくしたのでやめた

## 3. 中身の読み込みと描き直し

### 3.1 読み込み

- 中身を読むのは育児の段だけ（最新の授乳1件・計測中の印・授乳の間隔）。育児の段を含む重ねたものも同じ
- ログインの情報はアプリと同じ端末の保存（AsyncStorage）から読む。アプリでログインしていれば同じ人として読める
- 数え方はアプリの画面と同じ関数を使う。ウィジェット独自の数え方は作らない（`mobile/src/widgets/widgetData.ts`）

### 3.2 時間で古くならない出し方

- 30分ごとにしか描き直されない前提で、出すものを選ぶ（時刻）。残り時間・経過時間・進み具合の帯は出さない

### 3.3 描き直すとき

- 置いたとき・大きさを変えたとき
- 育児は30分ごと（`updatePeriodMillis`。Androidの最短）
- **アプリを開いたとき・前面へ戻したとき・背面へ回したとき**（`useWidgetRefresh`）。記録してホーム画面へ戻ったときには新しい目安になっている
  - 背面へ回した瞬間の描き直しは裏で止められて終わらないことがあり、一度「読めません」で描かれると、アプリを開いても戻らなかった（2026-10-17）。
    サーバーのログでは問い合わせは失敗しておらず、端末側で読み終える前に止まっていたとみている。前面にいる間にも描き直す
- 読めなかったときに目安の欄を押したとき（`WIDGET_CLICK` の `REFRESH_WIDGET`。`taskHandler.tsx`）
- 読めなかったとき（通信）は、1.5秒おいて1回だけ読み直す（裏で動き出した直後は通信がまだつながっていないことがある）
- パートナーの端末での記録は、次の30分ごとの描き直しか、自分がアプリを開いて閉じたときに出る
  （通知が届いたときに描き直すのは、まだしていない）

## 4. 開発のときの注意

- **`react-native-android-widget` には手を入れている**（`mobile/patches/react-native-android-widget+0.22.1.patch`。
  `npm install` のあと `patch-package` が当てる）。ライブラリを上げるときはこの差分が要るか確かめ、要れば作り直す
  - 元はボタンごとの押したときの処理（PendingIntent）を、番号に時刻（ミリ秒）を使い「前のものを取り消す」指定で作っていた。
    1回の描画で作るボタンはほぼ同じミリ秒になり、処理の中身も見分けがつかないので、後から作ったものが先のものを取り消し、
    **押しても何も起きないボタンができていた**（2026-10-14、3段のウィジェットで「おむつ」を押しても開かず、ほかのボタンも効かなかった）
  - 直し方: 番号はボタンごとの通し番号にする。リンク（`OPEN_URI`）は放送を経ずに、そのリンクを直接開く画面の PendingIntent にする
    （放送の受け手から画面を開く遠回りを避ける）。開くアプリも自分に固定したので、正式版と開発版（`.dev`）を両方入れた端末でも
    「どちらのアプリで開くか」は聞かれない
- **リンクは入口（`app/index.tsx`）を通す**（`sukusuku:///?to=care&open=milk`。`appLink`）。入口が `to`（タブ）と
  `open`（入力画面）を読み、お知らせのタップと同じ形（パスとパラメータ）でタブへ移す。最初のタブの設定には関係なく、押したタブが開く
  - 経緯（2026-10-14）: 最初は `sukusuku://care?open=milk`。`care` がホスト名として読まれ、タブも `open` も拾えなかった。
    次に `sukusuku:///care?open=milk`（タブのパスへ直接）にしたが、押すとアプリが一瞬開いてホーム画面へ戻り、
    「繰り返し終了しています」と出た（実機。原因のログは未取得）。毎回の起動で通る入口と、お知らせのタップで実績のある移し方に合わせた
- ウィジェットの部品はネイティブなので、入れたあとは `.apk` を作り直す（Expo Go では確かめられない）
