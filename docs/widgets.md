# ホーム画面のウィジェット（2026-10-14）

最初のタブに選べる4つ（予定・ToDo・育児・家計）を、ホーム画面からワンタップで開けるようにする。
よく使い、記録も多い育児・家計は、タブを開くだけでなく**入力画面まで直接開く**。

## 1. 範囲

- **ネイティブ版（Androidの `.apk`）だけ。** Expo Go・iOS・PWA版（`src/`）には無い
  （ルートの `CLAUDE.md`「ネイティブでしかできないもの」）。Expo Go には部品が入っておらず、
  読み込むだけで落ちるので、`mobile/src/widgets/availability.ts` で確かめてから読み込む
- 部品は `react-native-android-widget`。ウィジェットの見た目は JSX で書き、裏（ヘッドレスJS）で描く
- 置き方: ホーム画面を長押し →「ウィジェット」→「かぞく手帳」

## 2. 種類

| 名前（`widgetNames.ts`） | ピッカーの名前 | 大きさ | 中身 | 押すと |
|---|---|---|---|---|
| A. `TabLauncher` | タブ | 4×1（2×2 まで変えられる） | 予定・ToDo・育児・家計のボタン | そのタブを開く |
| B. `CareQuick` | 育児 | 4×2 | 前回の授乳・次の目安・4つのボタン | 授乳・おむつ・搾乳・体温の入力画面 |
| C. `MoneyQuick` | 家計 | 4×2 | 今月・今日の支出・4つのボタン | 支出・収入・振替の入力画面、レシートの撮影 |
| D. `ListItems` | ToDo・買い物 | 2×2（変えられる） | 1つのリストのまだ済んでいない項目 | そのリスト |

**配色はアプリと同じ（ライトだけ）。** アプリは `userInterfaceStyle: 'light'` で、端末がダークモードでも
ライトのまま出す。ウィジェットも同じで、ダーク用の絵は作らない（ルートの `CLAUDE.md`「配色」）。
色は `mobile/src/lib/theme.ts` をそのまま使う（育児の4つは記録の色、家計は家計タブの青、タブはタブバーの青）。

### 2.1 A. タブ

- 押したタブでアプリを開く。最初のタブの設定（`users.start_tab`）に関係なく、押したタブが開く
- データは読まない。ログインしていなくても、圏外でも同じように出る
- 横長なら横一列、正方形に近ければ2段に並べる

### 2.2 B. 育児

- **前回の授乳**と**次の目安**を時刻で出す（「9:40」「12:40」）。決め方は育児タブの見出しの「次の授乳」と同じ
  （`feedingSchedule.ts` の `resolveLastFeeding`・`nextFeedingSchedule`。家族の端末の計測中・記録待ちも前回の授乳に数える）
  - 家族のだれかが測っている間は「いま授乳中」
  - **「あと◯分」「◯分経過」は出さない。** ウィジェットは30分ごとにしか描き直されないので、時間とともに変わる値はすぐ古くなる。時刻なら古くならない
- ボタンはお知らせのタップと同じ飛び先（`/care?open=milk` など。`mobile/src/lib/appLinks.ts`）
- **ウィジェットから直接は保存しない。** 押し間違いで記録が増えないよう、必ずアプリの入力画面を通す

### 2.3 C. 家計

- 今月の支出と今日の支出。数え方は振り返りの「支出」と同じ（`buildMonthSummary` の `living`。振替は入れない）
- ボタン: 支出・収入・振替は記録の入力画面をその種類で開く（`/money?open=income` など）。レシートは撮影から始める（家計タブの「レシートを読む」と同じ）
- **金額を隠す設定**（設定の画面の「ホーム画面のウィジェット」）。ホーム画面は人に見られやすいので、この端末ごとに選ぶ（既定は出す）。隠すと見出しとボタンだけになる

### 2.4 D. ToDo・買い物

- 出すリスト: 暮らしタブの「買い出しリストへ送る」で選んだリスト（この端末で覚えている送り先）。
  無ければToDoタブの一覧の先頭（固定したリストが先）
- 並びはToDoタブで開いたときと同じ（グループの順 → 未分類、中は並び順）。入りきらないぶんは「ほか n件」
- 押すとそのリストをToDoタブで開く（`/list?list=<id>`）。済みにする・足すのはアプリで行う（ウィジェットからは書き込まない）

## 3. 中身の読み込みと描き直し

### 3.1 読み込み

- ログインの情報はアプリと同じ端末の保存（AsyncStorage）から読む。アプリでログインしていれば同じ人として読める
- 読めなかったときはボタンだけ出し、理由を一言添える（「アプリでログインすると表示されます」など）
- 読む量はウィジェットに要るものだけ（育児: 最新の授乳1件・計測中の印・授乳の間隔、家計: 今月の記録だけ、ToDo: リスト）
- 数え方はアプリの画面と同じ関数を使う。ウィジェット独自の数え方は作らない（`mobile/src/widgets/widgetData.ts`）

### 3.2 時間で古くならない出し方

- 30分ごとにしか描き直されない前提で、出すものを選ぶ（時刻・金額・項目）。残り時間・経過時間・進み具合の帯は出さない

### 3.3 描き直すとき

- 置いたとき・大きさを変えたとき
- 30分ごと（`updatePeriodMillis`。Androidの最短）
- **アプリを背面へ回したとき**（`useWidgetRefresh`）。記録してホーム画面へ戻ったときには新しい中身になっている
- パートナーの端末での記録は、次の30分ごとの描き直しか、自分がアプリを開いて閉じたときに出る
  （通知が届いたときに描き直すのは、まだしていない）

## 4. 開発のときの注意

- 正式版と開発版（`.dev`）を両方入れた端末では、ボタンを押したときに「どちらのアプリで開くか」を聞かれる
  （同じ `sukusuku://` のリンクを両方が受けるため）。家族の端末は正式版だけなので出ない
- ウィジェットの部品はネイティブなので、入れたあとは `.apk` を作り直す（Expo Go では確かめられない）

## 5. まだしていないこと

- 通知（FCM）を受けたときにウィジェットを描き直す（パートナーの記録をすぐ出す）
- ウィジェットから項目を済みにする（取り消しの手当てとセットで）
- 予定の直近を出すウィジェット（案F）
- PWA版の代わり（manifest の `shortcuts` で、アイコン長押しから同じ飛び先へ）
