# 家族総合管理アプリへの改修（設計）

子育て特化の「すくすく手帳」を、白石家の総合管理アプリ「**かぞく手帳**」に改修する。
本書は**設計を詰めるための叩き台**で、未決事項（§7）が決まり次第更新する。

## 1. 基本方針

- 初期バージョンのタブは **予定・リスト・育児・設定** の4つ
  - 予定・リスト: 現状のまま
  - 育児: ホームの「生後日数」「次の授乳」＋記録タブ全部＋保活タブを統合（位置は今の記録タブ）。
    ホームの産院・小児科等の発信ボタンは削除
  - 設定: アカウント情報・家族情報・通知設定に絞る。自由入力欄（カスタム項目等）は廃止
- **家族1人1人を「家族メンバー」としてDBで正しく持ち、アプリ全体がそれを参照する**
  （いまは名前がコードとDB制約に直書きされている。§2）
- 予定の「タスク」とリストは別の機能のまま。混ぜない
- mobile版が正、PWA版（`src/`）は同じPRか続きのPRで追従（CLAUDE.md）

## 2. 現状の問題（前提の確認）

| 問題 | 箇所 | 影響 |
|---|---|---|
| 家族の名前が直書き | `Participant = '大造' \| 'いづみ' \| '岳'`（types/app.ts）、色分け（uiUtils.ts）、`tasks_owner_check` 制約（0041） | 家族が増える・改名するたびにコードとmigrationの修正が要る |
| 本人と家族の対応が役割頼み | `users.role`（papa/mama）→ 名前の対応表 `ROLE_TO_PARTICIPANT` | 夫婦以外（子・祖父母）を表せない |
| 家族情報が自由入力のjsonb | `family_profiles.child_fields / family_fields / emergency_fields / custom_fields` | 型も検証もなく、生後日数の計算が `key: 'birthDate'` の文字列頼み |
| 子どもの情報が二重 | `children`（name, birth_date）と `family_profiles.child_fields` | どちらが正か不明 |
| `families` が2行 | 本番DB | 使われていない家族行がある可能性（移行時に確認） |

## 3. データ設計

### 3.1 新設・拡張するテーブル

**`families`（拡張）** — 世帯の情報
| 列 | 型 | 備考 |
|---|---|---|
| name | text | 表示名「白石家」 |
| postal_code | text | |
| address | text | |
| home_phone | text | 任意 |

**`family_members`（新設）** — 家族1人1人。アプリ内の「人」はすべてここを指す
| 列 | 型 | 備考 |
|---|---|---|
| id | uuid PK | |
| family_id | uuid FK families | RLS: `current_family_id()` と一致 |
| user_id | uuid FK users, unique, null可 | ログインする人だけ紐づく（子どもはnull） |
| relation | text check | `husband` / `wife` / `child` |
| display_name | text | 画面に出す短い名前（大造・いづみ・岳） |
| family_name / given_name | text | 氏名 |
| family_name_kana / given_name_kana | text | 任意 |
| birth_date | date | 年齢・生後日数はここから計算（保存しない） |
| phone | text | 携帯 |
| email | text | 任意（ログイン用メールとは別） |
| workplace / workplace_phone | text | 任意 |
| color | text | 予定の色分け。いまの青/桃/翠を初期値に |
| sort_order | int | 並び順 |
| created_at / updated_at | timestamptz | |

- **育児の対象**は `relation = 'child'` のメンバー。既存の `children` は `member_id`（FK, unique）を足して
  1:1でつなぎ、`growth_records.child_id` 等はそのまま使う（FKの付け替えを避ける）
- メンバーは**一家の3人だけ**（夫・妻・子）。migrationで3行を作り、アプリからの追加・削除はしない（編集のみ）
- `users.role` は `family_members.relation` に役目を譲り、移行後に参照をやめる

### 3.2 既存データの参照の付け替え

| 対象 | 現在 | 改修後 |
|---|---|---|
| `tasks.participants` | `text[]`（名前） | `uuid[]`（member id） |
| `tasks.owner` | `text` + 名前直書きのcheck | `uuid`（FK family_members） |
| 色分け | `uiUtils.ts` の switch | `family_members.color` |
| 生後日数 | `child_fields` の `birthDate` | 子メンバーの `birth_date` |

名前→idの付け替えは、本番DBのmigration（名前で突き合わせて変換）とアプリの切り替えを
**同時に**出す必要がある（docs/calendar.md §6 と同じ運用）。

### 3.3 家族情報の項目（要検討）

叩き台。◎=持つ、○=任意、×=持たない。

| 項目 | 世帯 | 夫・妻 | 子 | 備考 |
|---|---|---|---|---|
| 家名（白石家） | ◎ | | | |
| 郵便番号・住所 | ◎ | | | |
| 固定電話 | ○ | | | |
| 表示名（大造など） | | ◎ | ◎ | 予定・リストに出る名前 |
| 氏名・ふりがな | | ◎ | ◎ | |
| 生年月日（→年齢） | | ◎ | ◎ | 子は生後日数にも使う |
| 携帯電話 | | ◎ | | |
| メールアドレス | | ○ | | ログイン用とは別 |
| 勤務先・勤務先電話 | | ○ | | |
| 表示色 | | ◎ | ◎ | 予定の色分け |
| 産院・小児科 | × | × | × | 不要（決定） |
| マイナンバー・保険証番号・口座 | × | × | × | 漏れたときの害が大きいので持たない |

検討の候補（入れるなら追記）: 血液型、アレルギー、かかりつけ医以外の連絡先、記念日（結婚記念日など）。

### 3.4 アカウントごとの設定

| 列 | 置き場所 | 備考 |
|---|---|---|
| 最初に開くタブ | `users.start_tab`（`schedule` / `list` / `care` / `settings`、既定 `schedule`） | 夫婦で別々に選べる。端末を替えても引き継ぐ |

### 3.5 廃止するもの

- `family_profiles`（jsonbの自由入力）: 中身を `families` / `family_members` に移したあと、
  読み書きをやめ、1リリース置いてからdrop
- 緊急連絡先（産院・小児科）: 廃止。会社電話はメンバーの勤務先電話へ移す

### 3.6 個人情報の扱い

- 住所・電話・生年月日は家族内だけに見せる（既存と同じ `current_family_id()` のRLS）
- 生年月日から年齢を出すだけで、年齢は保存しない
- 通知やログに個人情報を載せない

## 4. 画面設計

### 4.1 タブ

| 順 | タブ | アイコン（案） | 中身 |
|---|---|---|---|
| 1 | 予定 | CalendarDays | 現状のまま |
| 2 | リスト | ListTodo | 現状のまま |
| 3 | 育児 | Baby | §4.2 |
| 4 | 設定 | Settings | §4.3 |

- ホーム・記録・保活の3タブは削除。アプリを開いたときの最初のタブは、設定で各自が選ぶ（§3.4）
- 通知等からの遷移先（`/log`・`/home` など）は `/care` に付け替え、旧パスはリダイレクトを残す

### 4.2 育児タブ

```
┌ 固定 ─────────────────────────┐
│ 岳 生後123日目（4ヶ月2日）      │ ← 1行に圧縮（ホームの大きなヒーローはやめる）
│ 次の授乳 14:30（あと45分）  [記録] │ ← NextFeedingCard
│ [記録] [成長] [保活]            │ ← 切り替え
├ スクロール ──────────────────────┤
│ 記録: タイムライン＋記録ボタン（ミルク/おむつ/搾乳/体温） │
│ 成長: 成長曲線＋記録             │
│ 保活: 園ごとの基本情報・見学チェックリスト │
└───────────────────────────────┘
```

- 中身は今の記録タブ・保活タブのコンポーネントをそのまま流用（`components/log`・`components/hokatsu`）
- 産院・小児科・会社への発信ボタンは削除

### 4.3 設定タブ

| セクション | 中身 |
|---|---|
| アカウント | 自分のメンバー情報（§3.3）、最初に開くタブ、ログイン中のメール、ログアウト |
| 家族 | 世帯情報（家名・住所・電話）、3人の情報の編集（追加・削除はなし） |
| 通知 | プッシュ通知のオン/オフ、授乳間隔の通知、体温リマインダー（育児の通知もここに統合） |
| アプリ情報 | バージョン |

- 「お子様の情報」「パパ・ママ情報」「緊急連絡先」「カスタム項目」の自由入力欄は廃止
- 編集は項目ごとの編集画面（モーダル）で行い、型に合った入力（日付・電話番号）にする

### 4.4 アプリ名・アイコン

- 表示名を「かぞく手帳」に変える（`mobile/app.config.js` の `name`、PWAのmanifest・タイトル、ストア掲載情報）
- アイコン（`mobile/assets/` のicon・adaptive icon・splash・通知アイコン、PWAのアイコン）を作り直す
- **パッケージ名・slug・Supabaseのプロジェクトは変えない**（変えると別アプリ扱いになり、更新で引き継げない）

## 7. 決定事項（2026-10-01）

1. 最初に開くタブ: 設定で各自が選ぶ
2. アプリ名: 「かぞく手帳」、アイコンも変える
3. 産院・小児科: 不要。家族情報の項目は §3.3 で検討を続ける
4. 家族メンバー: 一家の3人だけ
5. 授乳間隔・体温リマインダー: 設定の通知に統合
6. 予定のタスクとリストは別の機能のまま、混ぜない
