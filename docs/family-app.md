# 家族総合管理アプリへの改修（設計）

子育て特化の「すくすく手帳」を、白石家の総合管理アプリ「**かぞく手帳**」に改修する。
本書は**設計を詰めるための叩き台**で、未決事項（§7）が決まり次第更新する。

## 1. 基本方針

- 初期バージョンのタブは **予定・リスト・育児・設定** の4つ
  - 予定・リスト: 現状のまま
  - 育児: ホームの「生後日数」「次の授乳」＋記録タブ全部＋保活タブを統合（位置は今の記録タブ）。
    ホームの産院・小児科等の発信ボタンは削除
  - 設定: アカウント情報・家族情報・通知設定に絞る。自由入力欄（カスタム項目等）は廃止
- **家族1人1人を「家族メンバー」としてDBで正しく持ち、アプリ全体がそれを参照する**
  （いまは名前がコードとDB制約に直書きされている。§2）
- 予定の「タスク」とリストは別の機能のまま。混ぜない
- mobile版が正、PWA版（`src/`）は同じPRか続きのPRで追従（CLAUDE.md）

## 2. 現状の問題（前提の確認）

| 問題 | 箇所 | 影響 |
|---|---|---|
| 家族の名前が直書き | `Participant = '大造' \| 'いづみ' \| '岳'`（types/app.ts）、色分け（uiUtils.ts）、`tasks_owner_check` 制約（0041） | 家族が増える・改名するたびにコードとmigrationの修正が要る |
| 本人と家族の対応が役割頼み | `users.role`（papa/mama）→ 名前の対応表 `ROLE_TO_PARTICIPANT` | 夫婦以外（子・祖父母）を表せない |
| 家族情報が自由入力のjsonb | `family_profiles.child_fields / family_fields / emergency_fields / custom_fields` | 型も検証もなく、生後日数の計算が `key: 'birthDate'` の文字列頼み |
| 子どもの情報が二重 | `children`（name, birth_date）と `family_profiles.child_fields` | どちらが正か不明 |
| `families` が2行 | 本番DB | 使われていない家族行がある可能性（移行時に確認） |

## 3. データ設計

### 3.1 新設・拡張するテーブル

**`families`（拡張）** — 世帯の情報
| 列 | 型 | 備考 |
|---|---|---|
| name | text | 表示名「白石家」 |
| postal_code | text | |
| address | text | |
| home_phone | text | 任意 |

**`family_members`（新設）** — 家族1人1人。アプリ内の「人」はすべてここを指す
| 列 | 型 | 備考 |
|---|---|---|
| id | uuid PK | |
| family_id | uuid FK families | RLS: `current_family_id()` と一致 |
| user_id | uuid FK users, unique, null可 | アカウントを持つ人だけ紐づく。子は最初null、スマホを持ったら紐づける（§3.5） |
| is_guardian | boolean | 保護者（家族全員の情報を編集できる）。夫・妻はtrue、子はfalse |
| relation | text check | `husband` / `wife` / `child` |
| display_name | text | 画面に出す短い名前（大造・いづみ・岳） |
| family_name / given_name | text | 氏名 |
| family_name_kana / given_name_kana | text | 任意 |
| birth_date | date | 年齢・生後日数はここから計算（保存しない） |
| phone | text | 携帯（子もスマホを持ったら入れる） |
| email | text | 任意（ログイン用メールとは別） |
| workplace / workplace_phone | text | 勤務先と電話。子は所属（保育園・学校）と電話として使う。緊急時の連絡先 |
| color | text | 予定の色分け。いまの青/桃/翠を初期値に |
| sort_order | int | 並び順 |
| created_at / updated_at | timestamptz | |

- **育児の対象**は `relation = 'child'` のメンバー。既存の `children` は `member_id`（FK, unique）を足して
  1:1でつなぎ、`growth_records.child_id` 等はそのまま使う（FKの付け替えを避ける）
- メンバーは**一家の3人だけ**（夫・妻・子）。migrationで3行を作り、アプリからの追加・削除はしない（編集のみ）
- `users.role` は `family_members.relation` に役目を譲り、移行後に参照をやめる

### 3.2 既存データの参照の付け替え

| 対象 | 現在 | 改修後 |
|---|---|---|
| `tasks.participants` | `text[]`（名前。直書きの3人だけ） | `text[]`（家族メンバーの表示名） |
| `tasks.owner` | `text` + 名前直書きのcheck | `text`（家族メンバーの表示名。checkは外す） |
| 選べる名前・色分け | `types/app.ts`・`uiUtils.ts` の直書き | `family_members` の並び・`color`（`lib/familyRoster.ts`） |
| 生後日数 | `child_fields` の `birthDate` | 子メンバーの `birth_date` |

予定は **idではなく表示名のまま持つ**（0048）。端末に入っている前の版のアプリも名前で
読み書きするため、型をidに変えると新しい版を入れるまで前の版が動かなくなる。
そのかわり、表示名を変えたらDBのトリガーが予定の参加者・主体の名前も書き換える。
表示名は空にせず、家族の中で重ねない（制約）。

◎=持つ、○=任意、×=持たない。

| 項目 | 世帯 | 夫・妻 | 子 | 備考 |
|---|---|---|---|---|
| 郵便番号・住所 | ◎ | | | |
| 表示名（大造など） | | ◎ | ◎ | 予定・リストに出る名前 |
| 氏名（姓・名） | | ◎ | ◎ | カードの見出しはフルネーム。アカウントの「お名前」は名 |
| 生年月日（→年齢） | | ◎ | ◎ | 子は生後日数にも使う |
| 携帯電話 | | ◎ | ○ | スマホを持ったら | |
| 勤務先・勤務先電話（子は所属・電話） | | ◎ | ○ | 緊急時の連絡先として持つ（決定）。子は園・学校に入ったら | |
| 表示色 | | ◎ | ◎ | 予定の色分け |
| 産院・小児科 | × | × | × | 不要（決定） |

血液型・アレルギー・記念日などは一旦持たない。必要になったら追加する。

### 3.4 アカウントごとの設定

| 列 | 置き場所 | 備考 |
|---|---|---|
| 最初に開くタブ | `users.start_tab`（`schedule` / `list` / `care` / `settings`、既定 `schedule`） | 1人ずつ選べる。端末を替えても引き継ぐ |
| 育児タブを出すか | `users.show_care_tab`（既定 true） | 子のアカウントでは切れるように。切ったら最初のタブは予定に戻す |
| 通知 | 既存どおりアカウント（端末）ごと | 授乳・体温の通知も受け取るかを各自で選ぶ |

### 3.5 子どもが自分のアカウントを持つとき

子がスマホを持ったら、同じ家族の一員として自分のアカウントで使う。それまでは
アカウントの無いメンバー（`user_id` null）として親が情報を管理する。

**紐づけの流れ（招待コード）**
1. 保護者が 設定>家族 で子の「アカウントを作る」を押し、使い切りの招待コード（有効期限つき）を出す
2. 子が自分のスマホでアプリを入れ、自分のメールでログインし、コードを入れる
3. サーバー側の関数（`redeem_member_invite`、security definer）が、`users.family_id` と
   `family_members.user_id` を同時に設定する。コードは使った時点で無効

招待は `member_invites`（member_id, code_hash, expires_at, used_at）で持つ。
いまの夫・妻の紐づけ（`users.family_id` を手で設定）も、今後はこの仕組みに寄せられる。

**権限**（RLS）
| 操作 | 保護者 | 子（アカウントあり） |
|---|---|---|
| 世帯情報・全員の情報の編集 | ○ | ×（見るだけ） |
| 自分の情報の編集 | ○ | ○ |
| 招待コードの発行 | ○ | × |
| 予定・リスト | ○ | ○（「自分だけ」の予定・リストは作った本人だけ。既存の `is_private` と同じ） |

**アカウント側の前提**
- `users.role`（papa/mama の制約つき）には頼らない。続柄も権限もメンバー側（relation・is_guardian）で判断する
- 通知・最初に開くタブ・育児タブを出すかどうかは**アカウントごと**の設定にする
  （子のアカウントには授乳の通知を送らない、育児タブを出さない、を選べるように）
- 「本人」の判定は `users.role` から「自分の `user_id` に紐づくメンバー」に変える
  （予定の主体の初期値など。いまの `ROLE_TO_PARTICIPANT` を置き換える）

### 3.6 廃止するもの

- `family_profiles`（jsonbの自由入力）: 中身を `families` / `family_members` に移したあと、
  読み書きをやめ、1リリース置いてからdrop
- 緊急連絡先（産院・小児科）: 廃止。会社電話はメンバーの勤務先電話へ移す

### 3.7 個人情報の扱い

- 住所・電話・生年月日は家族内だけに見せる（既存と同じ `current_family_id()` のRLS）
- 生年月日から年齢を出すだけで、年齢は保存しない
- 通知やログに個人情報を載せない

## 4. 画面設計

### 4.1 タブ

| 順 | タブ | アイコン（案） | 中身 |
|---|---|---|---|
| 1 | 予定 | CalendarDays | 現状のまま |
| 2 | リスト | ListTodo | 現状のまま |
| 3 | 育児 | Baby | §4.2 |
| 4 | 設定 | Settings | §4.3 |

- ホーム・記録・保活の3タブは削除。アプリを開いたときの最初のタブは、設定で各自が選ぶ（§3.4）
- 通知等からの遷移先（`/log`・`/home` など）は `/care` に付け替え、旧パスはリダイレクトを残す

### 4.2 育児タブ

```
┌ 固定 ─────────────────────────┐
│ 生後123日目（4ヶ月2日）         │ ← 1行に圧縮（名前は出さない。ホームの大きなヒーローはやめる）
│ 次の授乳 14:30（あと45分）  [記録] │ ← NextFeedingCard
├ スクロール ──────────────────────┤
│ 記録: タイムライン＋記録ボタン（授乳/おむつ/からだ） │
└───────────────────────────────┘
```

- 使うのはほぼ「記録」だけなので、記録・成長・保活の切り替えはなくした（2026-10-02）
- **からだ**（旧「体温」ボタン）: 体温と身長・体重を記録して振り返る画面を開く。
  ボタンには平熱といちばん新しい体重を出す。画面の中で 体温 / 身長・体重 を切り替え、
  それぞれ記録ボタン・（身長・体重は成長曲線）・履歴の一覧がある。戻る操作で記録へ戻る。
  `mobile/src/components/care/BodyPanel.tsx`・`src/components/sukusuku/tabs/BodyPanel.tsx`
- **保活**: 設定タブの「保活」から開く（見学のときしか使わないため）。「表示する」を切ると
  入口ごと隠せる（端末ごとの設定）。mobile は `app/nursery.tsx`
  （`components/info/HokatsuSetting.tsx`）、PWA は設定タブ内の全画面（`HokatsuSetting.tsx`）
- 中身は今の記録タブ・保活タブのコンポーネントをそのまま流用（`components/log`・`components/hokatsu`）
- 産院・小児科・会社への発信ボタンは削除

### 4.3 設定タブ

| セクション | 中身 |
|---|---|
| 保活 | 「表示する」のトグル（端末ごと）と、見学チェックリストを開く行。トグルを切ると行は隠れる |
| アカウント | お名前（自分のメンバーの名。編集は「家族」で）、ログイン中のメール、招待コード、ログアウト。役割・パートナーは出さない。最初に開くタブ・育児タブを出すかは4で足す |
| 家族 | 自宅（郵便番号・住所）、3人の情報の編集（追加・削除はなし）、子のアカウント招待（保護者だけ） |
| 通知 | 1つの枠。トグルは「この端末で受け取る」の1つだけ（授乳の目安・検温の通知もこれで決まる）。授乳の間隔は3・4・5時間、検温は朝・夕の時刻。説明文は出さない |
| アプリ情報 | バージョン |

- 並びは 家族 → 通知 → 保活 → アカウント → アプリ情報
- 「お子様の情報」「パパ・ママ情報」「緊急連絡先」「カスタム項目」の自由入力欄は廃止
- 編集は項目ごとの編集画面（モーダル）で行い、型に合った入力（日付・電話番号）にする

### 4.4 アプリ名・アイコン

- 表示名を「かぞく手帳」に変える（`mobile/app.config.js` の `name`、PWAのmanifest・タイトル、ストア掲載情報）
- アイコン（`mobile/assets/` のicon・adaptive icon・splash・通知アイコン、PWAのアイコン）を作り直す
  - 絵柄: 白地に、屋根と「白」（白石家の頭文字）。「白」は点（ノ）を中央に寄せ、「日」の角を丸めて線で描く（書体に頼らない）
  - 配色: 屋根を3人の色（青・翠・桃）、「白」は墨色（D4）。「白」の点を屋根の頂点の真下にそろえる
  - 原図: `docs/family-app-icon.svg`。アイコン一式はここから書き出す
  - 単色版（通知・テーマアイコン）は屋根と「白」の線だけ
- **パッケージ名・slug・Supabaseのプロジェクトは変えない**（変えると別アプリ扱いになり、更新で引き継げない）

## 7. 決定事項（2026-10-01）

1. 最初に開くタブ: 設定で各自が選ぶ
2. アプリ名: 「かぞく手帳」、アイコンも変える
3. 産院・小児科: 不要。勤務先・勤務先電話は緊急時用に持つ（§3.3）
4. 家族メンバー: 一家の3人だけ
5. 授乳間隔・体温リマインダー: 設定の通知に統合
6. 予定のタスクとリストは別の機能のまま、混ぜない
7. 子もスマホを持ったら自分のアカウントで使う（§3.5）
8. 勤務先・勤務先電話は緊急時用に持つ。血液型等は一旦持たない
9. アイコン: 白地に屋根と「し」、屋根は3人の色（§4.4）
