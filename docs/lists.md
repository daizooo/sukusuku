# リスト機能（買い出し・やりたいこと・やること）の検討

いまGoogle Keepで作っている「買い出しリスト」「やりたいことリスト」「やることリスト」を
アプリ側に移すための検討メモ。きっかけは**買い出しリストの中でお店ごとに商品を
書き分けている**こと（Keepでは見出しを手で打つしかない）。

結論を先に書く。

- **柔軟さは「項目に好きな属性を付けられること」ではなく、「束ねる軸の呼び名を
  リストごとに変えられること」で足りる。** 買い出しなら「お店」、やりたいことなら
  「ジャンル」、やることなら「担当」。呼び名もグループ名も**自由入力**で、
  **軸は1つだけ持つ**（§3）。
- **グループを作らなければ、ただのチェックリストになる。** Todo用のリストは
  グループ0件のまま使えばよく、設定を増やさずに買い出し用とTodo用を使い分けられる（§3）。
- **項目には場所を持たせない。** 商品1つ1つにお店を打つのではなく、
  **追加先のグループを選んでから商品を打つ**（いまのKeepの使い方そのまま）（§4）。
- **Keepに対する本当の強みは場所ではなく、夫婦で同じリストが見えること**
  （家族の仕組みが既にある）**と、買ったものをもう一度足せること**（§2）。
- **「お店に着いたら通知」はPWAでは作れない。** iOSにジオフェンスの仕組みが無い。
  代わりに**お店で絞って表示する**（§7）。
- 日付のあるものは予定タブ、日付のないものはリストタブ。**同じものを2か所に置かない**（§5）。
- 入口（タブをどうするか）は好みが大きいので**決めてもらう**（§6・§10）。

---

## 1. いまの困りごとと、本当の課題

Keepの買い出しリストは、こう使っている。

```
■ イオン
 □ 牛乳
 □ おむつ M
■ ドラッグストア
 □ 粉ミルク
```

見出しが**ただの文字**なので、次のことができない。

| できないこと | 何が起きるか |
| --- | --- |
| お店で絞る | 店にいる間、関係ない商品も一緒に目に入る |
| 項目のお店を変える | 行を切って貼り直す |
| 買ったものを消す/戻す | チェックを外して並べ直すか、また打ち直す |
| 定番をもう一度足す | 牛乳・おむつを毎回打ち直す |

つまり課題は「場所を設定したい」ではなく、**見出しが構造になっていないこと**。
ここを直せば、やりたいこと（ジャンル別）もやること（担当別）も同じ仕組みで載る。

## 2. Keepではなくアプリに置く理由

場所だけが理由なら、正直Keepのままでもよい。移す価値があるのは次の2つ。

- **夫婦で同じリストが見える。** このアプリは既に家族単位（`family_id`）で
  データを共有していて、招待も済んでいる。Keepの共有は別途アカウントを
  招待する必要がある。「買い足しておいて」がリストに書けば伝わる状態は、
  予定・記録を共有しているのと同じ効き方をする。
- **買ったものをもう一度足せる。** 買い出しは**同じ品を繰り返し買う**ので、
  完了した項目を消さずに持っておけば「よく買うもの」から1タップで戻せる。
  Keepは「チェック済みを削除」しかないので、毎回打ち直しになっている。

この2つが無いなら、作らずにKeepを使い続けるほうが早い。**逆に言えば、
この2つを満たさない設計にはしない。**

## 3. データの持ち方

3つのテーブルに分ける。既存の `tasks` には**足さない**（理由は§5）。

### lists（リスト）

| 列 | 内容 |
| --- | --- |
| `id` / `family_id` | 家族単位で共有。RLSは既存の `current_family_id()` に合わせる |
| `name` | 「買い出し」「やりたいこと」など |
| `group_label` | **束ねる軸の呼び名**。「お店」「場所」「ジャンル」「担当」など**自由入力**。既定は「グループ」 |
| `position` | リストの並び順 |
| `is_pinned` | **一覧の先頭に固定するか**（Keepのピン止め。2026-09-15に追加。`0035_list_pin.sql`） |
| `is_private` / `created_by` | **共有設定**（自分だけ/共有）と作成者。2026-09-23に追加（`0044_list_privacy.sql`、§3.1） |

### list_groups（グループ）

| 列 | 内容 |
| --- | --- |
| `list_id` | どのリストのグループか |
| `name` | 「イオン」「ドラッグストア」など**自由入力**（候補を用意して縛らない） |
| `position` | 並び順 |

**グループは0件でもよい。** 1件も作らなければグループの見出しも絞り込みのチップも
出ないので、**ただのチェックリスト**になる。買い出し用（お店で分ける）とTodo用
（分けない）の使い分けが、リストごとの設定項目を増やさずに成り立つ。

### list_items（項目）

| 列 | 内容 |
| --- | --- |
| `list_id` / `group_id` | `group_id` が null なら「未分類」。**グループを使わないリストでは常に null** |
| `title` | 「牛乳」「おむつ M」。数量はタイトルに書く（§9） |
| `is_done` / `done_at` | 完了は**消さずに残す**（§2の「もう一度足せる」ため） |
| `position` | グループ内の並び順 |

### なぜ軸を1つに絞るのか

項目に好きな属性（値段・期限・優先度…）を足せる作りにもできるが、採らない。

- 実際の使い分けは**どれも「1つの軸で束ねる」に収まる**。お店・ジャンル・担当を
  同時に使いたい場面が今の運用に無い。
- 属性を増やすほど**追加が1タップで終わらなくなる**。買い出しは「思い出した瞬間に
  打ち込む」ものなので、入力が重くなった時点で使われなくなる。
- 足りなくなったら、軸を2本目に増やすのではなく**リストを分ける**ほうが素直
  （例:「買い出し（日用品）」「買い出し（ベビー）」）。

### 3.1 共有設定（2026-09-23に追加）

予定・タスク（docs/calendar.md §1「共有設定」）と同じ2択を、リストにも持たせる。

- 単位は**リスト**。項目ごとには持たせない（追加のたびに選ぶことになり、
  「思い出した瞬間に打ち込む」手数が増えるため。§3 の軸を1つに絞る判断と同じ）
- **新しく作るリストの既定は「自分だけ」。** 家族に見せたいものだけ、
  リストの設定で「共有（家族全員）」へ切り替える
  （予定は既定が共有。リストは個人のメモとして使うことが多いので逆にしてある）
- 「自分だけ」のリストは、**中のグループ・項目もまとめて**他の家族には見えない
- 表示の制御はアプリ側の絞り込みではなく **RLS** で行う
  （`is_private = true` の行は `created_by = auth.uid()` の人しか参照・更新・削除できない）
- **既にあるリストはすべて共有のまま。** DB側の既定も共有(false)にしてあり、
  「自分だけ」にするのは画面で切り替えたときだけ
- 共有設定が入る前に作ったリストは作成者(`created_by`)を持たない。これを
  「自分だけ」に切り替えたときは、切り替えた本人を作成者として入れる
  （入れないと誰にも見えなくなるため）
- 画面では、一覧のカードと開いた先の見出しに**錠前**を添える（予定の一覧と同じ印）

## 4. 画面

新しい「リスト」タブ。CLAUDE.mdの方針どおり、**面全体はスクロールさせない**。

- **一覧（最初に出る面。2026-09-15に変更）**
  - Keepのメモ一覧と同じく、**リストを2列のカードで並べる**（1画面に4〜5つ見える）。
    カードには未完了の項目を先頭から数件（グループがあるときは名前つきで）出し、
    入りきらないぶんは「+n件」にまとめる。**切り替えのチップは無くし、カードを押して開く**。
  - 読むだけの面にして、チェックや追加は開いた先で行う（一覧での押し間違いを避ける）。
  - 末尾に「リストを追加」の枠を置く。
  - **ピン止め（2026-09-15に追加）**: カード右上のピンで一覧の先頭へ固定できる
    （Keepと同じ）。固定したものは「固定」「その他」に分けて並べる。
    固定を外しても並び順は変えないので、外すと元の場所へ戻る。
  - **並べ替え（2026-09-15に追加）**: カードを**長押ししてそのまま動かす**（Keepと同じ）。
    モードにも矢印にも入らない。動かせるのは同じ枠の中（固定は固定の中、
    その他はその他の中）だけで、固定するかどうかはピンで決める。
- **リストを開いたあとの上部（固定）**
  - 戻る・リスト名・リストの設定
  - **追加欄を常に一番上に置く。** 打ち込んで改行すれば即追加（Keepと同じ手数）。
    追加欄の横に**追加先のグループ**が出ていて、選んでから打つ＝**今のやり方そのまま**。
    **商品1つ1つにお店を設定する操作は無い**（打ち込むのはタイトルだけ）
  - グループのチップ（「すべて / イオン / ドラッグストア …」）。**ここで絞る**のが
    「お店にいるとき」の使い方（§7）
- **スクロールするのは項目の一覧だけ**
  - グループごとの見出し＋折りたたみ
  - 完了した項目は打ち消し線でグループの末尾へ。`完了を隠す` の切り替えあり
  - **書き換えは枠の中で終える（2026-09-17に変更）**: 項目をタップするとその行が
    入力欄になり、**内容だけ**をその場で直す。**項目のためだけの画面（「項目」の
    ダイアログ）は出さない**。Keepと同じで、追加・書き換え・削除がすべて同じ枠の
    中で済む。入力欄の外へ触れるか改行すれば保存、Escで取り消し。内容を空にした
    まま離れたときは元に戻す（消すのは行の×）。
  - **項目が持つのは内容だけ（2026-09-17に変更）**: メモは廃止した（`0036_list_items_drop_note.sql`）。
    補足は「牛乳 2本（低脂肪）」のように内容へ書く。入れ先のグループを選び直す操作も
    持たない（入れ直したいときは消して、その枠で打ち直す）。
  - グループの名前も**見出しをタップしてその場で直す**（リストの設定を開かなくてよい）。
- **並べ替え（2026-09-15に追加）**
  - 項目は**長押ししてそのまま動かす**。動くのは**同じグループの中だけ**
    （グループは打った枠で決まる。入れ直したいときは消して打ち直す）。
  - グループの枠ごと動かすときは**見出しを長押しする**（中の項目と取り合わない）。
  - 押してすぐ指が動いたときはスクロールとみなし、持ち上げない。持ったまま画面の
    上下に寄せると自動でスクロールする。仕組みは `ui/useDragReorder.ts`。
- **下部**
  - 「まとめて消す」。**完了した項目は既定で畳んである**ので、普段は消さなくても
    邪魔にならない。押したときは実際に削除する（「消す」と書いてあるものが
    残り続けるほうが分かりにくいため）
    - フェーズ2の「よく買うもの」は、**まだ消していない完了項目**から出す。
      毎回まとめて消す使い方をしていると候補が溜まらないので、そのときは
      別に「定番」を持つかどうかを作る前に確かめる

## 5. 予定タブとの境界

`tasks` は**日付で決まるもの**（カレンダー・リマインダー・出生日基準）で、
リストは**日付を持たないもの**。この線を引かないと、同じ「やること」が
2か所に増える。

- **リストの項目に日付は持たせない。** 期限が要るものは予定にする。
- 逆に**リストの項目を予定へ送る**導線（「予定にする」）は用意する価値がある
  （フェーズ3）。リストで温めたものを日付が決まった時点で予定へ移す流れになる。
- いまKeepにある「やることリスト」は、**日付が付いているものは予定タブへ**、
  付いていないものだけリストへ入れる。

## 6. 入口（タブ）をどうするか

いまのボトムバーは5つ（ホーム/予定/記録/保活/設定）。リストは**毎日開く**ものなので、
奥に隠すと使われない。案は3つ。

| 案 | 中身 | 評価 |
| --- | --- | --- |
| A. 6タブにする | バーに「リスト」を足す | 375px幅で1枠62px。アイコン＋11pxのラベルは入るが窮屈にはなる |
| B. 保活を設定の下へ移す | バーは5つのまま | 保活は一時期だけのもの・リストは毎日。**使用頻度の順としては正しい**が、保活の中身（園ごとのチェックリスト）が重く、移設の手間が別途かかる |
| C. 予定タブの5つ目の面にする | 月/週/日/リスト＋買い出し | 予定タブが既に4面を持つので**切り替えが二重**になり分かりにくい。採らない |

**A（6タブ）で進めることにした**（2026-09-14）。まず足して使ってみて、窮屈だと
感じたらBへ移す（Bは後からでもできる）。

## 7. 「場所」について — できることとできないこと

- **できない: お店に着いたら通知。** ジオフェンス（Geofencing API）はiOSのSafariに
  無く、PWAでは実現できない。ネイティブ版は凍結中（docs/native-app-rewrite.md）。
  **通知を前提にした設計にはしない。**
- **できる: お店で絞って表示する。** 店に入ったらチップを1つ押すだけで、その店の
  ぶんだけが並ぶ。実質これで足りる。
- **できる（フェーズ3）: ホームに「買い出し n件」を出す。** 出かける前に気づける。

## 8. 進め方

| フェーズ | 中身 | ここまでで |
| --- | --- | --- |
| 1 | リスト・グループ・項目のCRUD、グループで絞る、完了の表示切り替え | **いまのKeepの運用がそのまま移る** |
| 2 | 「よく買うもの」から再追加（完了履歴の頻度順）、リスト/グループの並べ替え | Keepより速くなる |
| 3 | 「予定にする」で `tasks` へ、ホームに件数 | 予定・記録とつながる |

フェーズ1だけでも移行できる形にする（フェーズ2を待たない）。

2026-09-15にフェーズ2のうち**ピン止め（Keepの固定）とリスト・グループ・項目の並べ替え**を
入れた（`0035_list_pin.sql`）。並べ替えはKeepと同じ**長押しして動かす**形。
残っているのは「よく買うもの」からの再追加。

2026-09-23に**共有設定（自分だけ/共有）**を足した（`0044_list_privacy.sql`、§3.1）。
新しく作るリストの既定は「自分だけ」で、既にあるリストは共有のまま。

2026-09-17に**項目の書き換えを枠の中へ移した**（§4）。項目をタップすると出ていた
「項目」のダイアログは廃止し、その行を入力欄に変える形にした。Keepと同じく
追加・書き換え・削除が枠の中だけで完結する。あわせて**項目のメモを廃止**し、
項目が持つのは内容だけにした（`0036_list_items_drop_note.sql`）。

コンフリクトの観点では、追加は**新規ファイル中心**で、既存への変更は
`TabId` / `NAV_ITEMS` / タブの分岐への**追記のみ**に収まる（CLAUDE.mdの方針どおり）。
マイグレーションは `0034_lists.sql` として1本足す。

## 9. 検討して見送ったもの

| 見送るもの | 理由 |
| --- | --- |
| 項目ごとの自由な属性（Notion風） | §3のとおり。入力が重くなり、2人の運用には過剰 |
| 数量の専用欄（牛乳 × 2） | 「牛乳2本」とタイトルに書けば足りる。欄が増えるほど追加が遅くなる |
| 1つの商品を複数のお店に紐づける | 実際には「どこで買うか」は決め打ちできる。要るなら項目を2つ作る |
| ~~ドラッグ＆ドロップの並べ替え~~ | 当初は実装コストとライブラリ増を理由に見送ったが、**長押ししてから動かす**形にすればどちらも避けられるため2026-09-15に実装した。長押しを挟むのでスクロールと取り合いにならず、Pointer Eventsだけで書けるのでライブラリも増えない（`ui/useDragReorder.ts`） |
| リストの種類ごとの専用画面 | 買い出し専用にすると、やりたいこと・やることが載らない。**同じ形で全部載る**ことを優先する |

## 10. 決まったこと（2026-09-14）

| 論点 | 決定 |
| --- | --- |
| 場所 | **自由入力のグループで分ける。** 通知は作らない（§7）。項目ごとに場所は持たせない |
| リストごとの使い分け | **グループを作るかどうかで決まる。** 0件ならただのチェックリスト（§3） |
| 入口 | **A案（6タブ）**。窮屈ならあとでB案（保活を設定配下へ）に移す（§6） |

この決定でフェーズ1（§8）の実装に入る。
