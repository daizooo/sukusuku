# 夜間の授乳「起床アラーム」の仕様

夜の授乳で寝過ごすことがあるため、**次の授乳の目安の15分前に、起きられる音で鳴らす**。
あわせて、夜に鳴ってほしくない端末（授乳しない側）の通知を止める。

> 状態: 仕様を合意し、§9の1〜3は実装済み（ネイティブ `modules/nursing-alarm`、`wakeAlarm.ts`、`0052`・`0053`）。実機での確認はこれから（2026-10-09時点）。

## 1. 決めたこと

| 項目 | 決定 |
| --- | --- |
| 鳴らす時刻 | 次の授乳の目安（`due_at`）の**15分前**。選択肢は設けない |
| 鳴らす条件 | `due_at` が「おやすみ時間」の中にあるとき（目安の時刻で判定） |
| 優先するもの | **確実に鳴ること**。サーバー経由ではなく、端末自身が予約する |
| 設定の単位 | **端末ごと**（家族では共有しない）。既定はオフ |
| 鳴らす端末 | 夜に授乳する側のAndroid（現状は妻の1台）。もう一方のAndroidは触らない＝鳴らない |
| iPad（Web版） | 起床アラームは鳴らない（ネイティブ専用。`CLAUDE.md` の方針どおりWebに反映しない） |
| スヌーズ | なし。**止められなかったときだけ5分後に1回**再鳴動 |
| おやすみ時間中の従来通知 | **端末ごとに止められる**（§6）。起床アラームとは別の設定 |

端末が1人1台ずつなので、「担当端末を1台に絞る」仕組みは作らない（サーバーに列も足さない）。

## 2. 設定（設定タブ。端末ごとにローカル保存）

- **起床アラーム**: オン/オフ（既定オフ）
- **おやすみ時間**: 開始〜終了（既定 22:00〜6:00。日をまたぐ）。時刻は日本時間
- **おやすみ時間は通知を止める**: オン/オフ（既定オフ。§6）
- 注意書き: 「おやすみモード（サイレント）で“アラームも止める”設定にしていると鳴りません」

おやすみ時間は「起床アラームの対象」と「通知を止める範囲」の**両方に使う同じ設定**にする
（夜の時間帯を2回入れさせない）。

## 3. いつ鳴らすか

次の目安は、今のホームの「次の授乳の目安」と同じ計算を使う
（`mobile/src/lib/feedingSchedule.ts`。いちばん新しい授乳の記録 + 間隔。
母乳の記録待ちは止めた時刻 + 間隔）。

```
鳴らす時刻 = due_at − 15分
予約する   = 起床アラームがオン && due_at がおやすみ時間の中 && 鳴らす時刻が今より後
```

- 判定は**目安の時刻（`due_at`）**で行う。鳴らす時刻が時間の外にはみ出ても鳴らす
  （例: おやすみが 22:00〜6:00、`due_at` が 6:00 の少し前なら、鳴らす時刻は 5:45 で問題ない）。
- **授乳中（母乳を計測中）は予約しない**。記録待ちは止めた時刻から数え直す。
- 記録がまだ1件も無い家族は予約しない。
- 鳴らす時刻がすでに過ぎているときは**いきなり鳴らさない**（遅れて記録した場合など）。
  このときは目安の時刻の通知（従来）が拾う。
- 記録が入るたびに次の目安が決まるので、**夜通し1回ずつ連鎖する**。記録が入らなければ次は立たない。

## 4. どう予約するか（確実さの作り方）

- Androidの `AlarmManager.setAlarmClock` で予約する。省電力（Doze）の最中でも時刻どおりに
  発火し、「正確なアラーム」の権限も要らず、発火時に前面サービスを始めることも許される。
- 予約は端末に持つ。サーバーや通信には頼らない（圏外・機内モードでも鳴る）。
  予約した時刻はネイティブ側（SharedPreferences）にも控え、再起動で消えたら
  `BOOT_COMPLETED` で掛け直す。
- **予約し直すきっかけ**（毎回、古い予約を取り消してから組み直す）:
  1. アプリを開いた・前面に戻ったとき
  2. 授乳を記録・修正・削除したとき
  3. 間隔・おやすみ時間・起床アラームの設定を変えたとき
  4. 端末の再起動
  5. 鳴り終えて停止したとき（次の予約を組む）
- 自分が記録する運用（夜の授乳をする本人の端末）なら、記録のたびに1.〜2.で必ず組み直される。
  **他人が記録した場合**に端末が気づけるのは、次にアプリを開いたとき・家族の同期が届いたときだけ。
  その間に古い予約が鳴ること（空振り）は許容する。寝過ごすよりよいため。
  鳴る直前にサーバーへ最新の記録を確認する案は、通信失敗時の扱いと認証の持ち方が重いので**今回は入れない**（§10）。

### 他の端末（PWA・パートナー）で記録されたとき（2026-10-04に追加）

端末は自分で記録したときしか予約を組み直せないので、PWAやパートナーの端末での記録には
気づけず、古い時刻に鳴って本当の時刻には鳴らなかった。そこで**サーバーが追従させる**。

- 端末が、起床アラームの設定（オンか・おやすみ時間）を自分の宛先の行へ写す
  （`push_subscriptions.wake_alarm_enabled` / `wake_quiet_start` / `wake_quiet_end`。`0053`）。
- `send-feeding-reminders`（1分おきに動く）が、その端末の「いま予約しているべき鳴らす時刻」を
  アプリと同じ規則（`_shared/wakePlan.ts`）で求め、**前回伝えた時刻と違うときだけ**、
  画面に出ないFCMのデータ通知（`kind = "wake-sync"`）で端末へ伝える。伝えた内容は行に控える
  （`wake_synced_trigger_at`）。
- 端末のネイティブ側（`WakeSyncMessagingService`）が、アプリが閉じていてもそれを受け取って
  目覚ましを入れ替える。JSも通信も要らない。expo-notifications のサービスを継いでいるので、
  起床アラーム以外の通知はこれまでどおり扱われる。
- 記録から入れ替わるまでは最大1分ほど。誰が記録しても同じ。
- 鳴らす時刻を過ぎたあとは端末へ送らず控えだけ消す（鳴ったあとに端末が入れる5分後の再鳴動を、
  取り消してしまわないため）。
- 授乳中（`nursing_alarms` に行がある家族）は予約なしと判断する。端末の画面は記録待ちを
  止めた時刻から数えるが、サーバーは記録が入ってから予約する（保存すれば追いつく）。

## 5. どう鳴らすか

- 授乳中のサービス（`NursingAlarmService`）とは**別の前面サービス**（`WakeAlarmService`）と、
  起床用の音（`WakeTonePlayer`）で鳴らす。授乳中の動きに影響させないため。
  音の出し方は `AlarmTonePlayer` と同じ（アラーム用の音量なので、マナーモードでも鳴る）。
- 音: 小さく始めて約20秒かけて大きくなる、目が覚める音。長さは**最大60秒**で自動で止まる。
  授乳中の区切りの短い音とは別物にし、聞き分けられるようにする。
- 常駐通知に「そろそろ授乳です（◯時◯分の目安）」と**「起きた」ボタン**を出す。
  ボタンかアプリを開く操作で止まる。
- **止められなかったとき**（60秒の自動停止まで操作がなかった）は、**5分後に1回だけ**同じ鳴り方を繰り返す。
  2回目も止められなければそれ以上は鳴らさない。目安の時刻に従来の通知が届く。
- 全画面での表示（画面を勝手に点ける）はしない。Android 14以降は通話・アラーム専用アプリでないと
  許可が出にくく、音で起きられれば足りるため。

## 6. おやすみ時間中の従来通知を止める（端末ごと）

今の「次の授乳」の通知は、目安の時刻に**家族の全端末**へ届く。授乳しない側が夜に起こされないよう、
端末ごとに止められるようにする。

- 対象は `feeding` 種別（次の授乳の目安）の通知だけ。予定のリマインダーや検温などは止めない。
- 端末の購読（`push_subscriptions`）に、おやすみ時間の開始・終了（日本時間）を**空を許す列**で持つ。
  `send-feeding-reminders` が、その端末の目安の時刻（`due_at`）がおやすみ時間の中なら、その端末だけ送らない。
  配信の記録は残さない（目安の時刻は変わらず、次の実行でも同じ判断になるだけで二重送信の心配がないため）。
- 起床アラームをオンにした端末では、**この設定は既定オフのままにする**。目安の時刻の通知が
  起床アラームを聞き逃したときの2段目になるため。
- 授乳しない側（夫）の端末ではオンにする。起床アラームはオフのままなので、夜は静かになる。
- Web版（iPad）には置かない。Web Push は撤去済みで、`send-feeding-reminders` は `fcm` にしか送らない
  ので、iPadにはそもそも「次の授乳」の通知が届かない。

## 7. 家族の端末ごとの見え方

| 端末 | 起床アラーム | 目安の時刻の通知（おやすみ時間中） |
| --- | --- | --- |
| 妻のAndroid | オン | 鳴る（2段目として残す） |
| 夫のAndroid | オフ（既定） | 止める（§6をオン） |
| iPad（Web版） | 鳴らない | 届かない（Web Push 撤去済み） |

## 8. 注意・リスク

- 機種によっては省電力の設定でアプリが止められ、予約が消えることがある。実機（妻の端末）で
  一晩試して確かめる。それでも消えるようなら、電池の最適化から外す案内を設定画面に出す。
- 相手が記録したあとに古い予約が鳴る空振りがありうる（§4）。止めれば済むが、許容できるか
  使いながら見る。
- 夜間に授乳しない側が誤ってオンにしても、その端末で鳴るだけで他の端末には影響しない
  （設定を共有しないため）。

## 9. 実装の順番（別々のPR）

1. **ネイティブ**: `modules/nursing-alarm` に「起床アラームの予約・取消」「発火の受け口」
   「起床用の鳴り方」「『起きた』ボタン」「再起動での掛け直し」を足す
2. **mobileのJS**: 予約の計算（純粋関数。`feedingSchedule.ts` と同じようにテストを付ける）、
   予約し直すきっかけの配線、設定タブの項目
3. **サーバー**: 購読に列を足す migration、`send-feeding-reminders` で端末ごとに送らない判定、
   設定タブの「おやすみ時間は通知を止める」
   （Web版への反映は不要。§6）

2の純粋関数は、境界（日またぎ・過ぎた時刻・授乳中・記録待ち）を網羅するテストを先に書く。
